# WFS-115 — [URGENT] Menus : « Continuer » après le choix d'un mode ramène au menu principal
Épic : E8 · Priorité : P1 Urgent · Dépend de : — · Taille : 2 h à 1 jour · Retour de l'utilisateur (test réel, 2026-11-05) : « quand je clique sur un mode et que je clique sur continuer, il me montre la page menu »

## Besoin
Après le choix d'un mode de jeu, le bouton qui fait avancer (« Continuer » / « Rouler ») ramène à l'écran du menu principal au lieu d'enchaîner sur l'écran suivant (choix du terrain, puis course). Le parcours menu → mode → terrain → course doit toujours avancer.

## Règles de gestion
- RG-01 : **reproduire d'abord** sur la dernière version de `main` : tester **chaque chemin** du menu (Course solo, Duel, Showroom / « Ta voiture », Réglages, et les modes de course quand ils existent) avec les boutons « Continuer », « Rouler » et « Retour ». **Nommer la cause au journal** (mauvais écran de destination dans `allerA(...)`, bouton « Retour » et « Continuer » superposés ou zones de toucher qui se chevauchent, état du mode perdu, double appui, écran suivant qui n'existe pas encore et renvoie au menu).
- RG-02 : si le bouton « Continuer » n'existe pas dans le code de `main` (le texte actuel est « Rouler » sur l'écran du terrain), vérifier si l'utilisateur teste une **ancienne version** : la Release `apercu` doit porter le dernier commit (WFS-106) ; le noter au journal.
- RG-03 : un appui sur « Continuer » mène **toujours** à l'écran suivant du parcours ; seul « Retour » (ou le bouton Menu) ramène en arrière, et d'un seul cran.
- RG-04 : le choix du mode est conservé d'un écran à l'autre (WFS-24) ; aucun écran vide ni retour inattendu.
- RG-05 : test CPU de navigation : enchaîner menu → mode → terrain → course et revenir ; aucun retour imprévu au menu (journal « Écran : a → b »).

## Critères d'acceptation
- [ ] test CPU : tous les chemins avancent ; captures `parcours-mode`, `parcours-terrain`, `parcours-course` ; cause documentée ; l'utilisateur confirme sur téléphone


## Précision de l'utilisateur et cause probable trouvée par le PO (2026-11-05)
- **Parcours exact** : « Course solo » → choix du mode → « CONTINUER » → (garage) → retour à la **page d'accueil du menu**.
- **Cause probable (lue dans le code de `main`)** : `src/game/modes_ecran.cpp` (`valider`) envoie « Continuer » vers **`Ecran::Garage`** ; dans `src/ui/garage.cpp` (≈ ligne 291) le bouton **« Choisir »** fait `g.allerA(Ecran::Menu)` : après avoir choisi sa voiture, le joueur **retombe sur l'accueil** au lieu d'aller au choix du terrain. Le bouton « Retour » du garage ramène aussi au menu (normal).
- **Correction attendue** : quand le garage a été ouvert **depuis le parcours d'une course** (Course solo → mode → Continuer), « Choisir » mène à **`Ecran::Terrain`** (choix du terrain et du moment), puis « Rouler » lance la course. Quand le garage est ouvert depuis le menu (Showroom, « Ta voiture »), « Choisir » ramène au menu comme aujourd'hui. Mémoriser « d'où vient le joueur » (drapeau de parcours) sans changer le noyau (accroche ≤ 10 lignes annoncée au journal).
- **Vérifier aussi** le mode Duel (Continuer → salon) et la Course à 5 voitures (distance choisie conservée jusqu'au terrain).
- **Précision de l'utilisateur** : ce n'est **pas** un plantage de l'application, c'est un défaut de développement (parcours mal enchaîné). Pas de recherche de plantage.
- **Leçon à appliquer** : tout ticket qui ajoute ou modifie un écran doit inclure un **test de parcours complet** (de l'accueil jusqu'à la course et retour) et le lister au journal avant fusion.
