# WFS-132 — Le jeu annonce une nouvelle version de l'APK (« Télécharger » en un appui) + boutons de volume sur le son du jeu
Épic : E7 · Priorité : P2 Haute · Dépend de : WFS-87 ✅ (Release `apercu` fiable), WFS-118 ✅ (signature fixe : installation par-dessus), WFS-126 ✅ (boîte de plantage)

## Besoin (qui, quoi, pourquoi)
L'utilisateur teste lui-même l'APK de `main` sur son téléphone, plusieurs fois par jour. Aujourd'hui il doit aller sur
GitHub, retrouver la Release `apercu` et comparer les numéros. Le jeu doit le lui dire tout seul au lancement :
« Nouvelle version disponible — Télécharger », puis l'APK s'installe par-dessus (WFS-118) et garde la sauvegarde.
En plus, les boutons de volume du téléphone doivent régler le son du jeu (média), même dans les menus silencieux.

## Règles de gestion
- RG-01 : **Quand** : au lancement (`onCreate` de `JeuActivity`), dans un thread Java d'arrière-plan, jamais sur le
  thread du jeu ni sur le thread d'interface ; au plus **une fois toutes les 6 h** (horodatage dans les `SharedPreferences`
  `wfs_maj`) ; délai réseau **5 s** (connexion et lecture) ; sans réseau, erreur HTTP, réponse illisible : **rien à l'écran**,
  une seule ligne au logcat `MISEAJOUR …` (raison). Le démarrage du jeu n'attend jamais la réponse.
- RG-02 : **Source** : `GET https://api.github.com/repos/wlfaleh/waforspeed_mobile/releases/tags/apercu` (dépôt public, sans
  jeton), en-têtes `Accept: application/vnd.github+json` et `User-Agent: WaForSpeed-Android`. Lire `name`
  (format écrit par `tools/qa/publier_apercu.sh` l. 113 : `Aperçu — construction N (abcdefg)`) avec l'expression
  `construction (\d+) \(([0-9a-f]{7})\)`, et l'adresse `browser_download_url` de la pièce jointe nommée `WaForSpeed.apk`.
  Pièce absente ou titre sans numéro : rien à l'écran (RG-01).
- RG-03 : **Comparaison** : numéro distant N contre `versionCode` de l'APK installé (= `GITHUB_RUN_NUMBER`,
  `android/app/build.gradle` l. 12). Boîte affichée **seulement si N > versionCode**. `versionCode == 1` (APK construit
  hors CI) : jamais de boîte. La règle est une **fonction Java pure** (`MiseAJour.analyser(json, versionCode, ignoree)`)
  testée par JUnit (RG-08).
- RG-04 : **Boîte** (Java `AlertDialog`, thème sombre comme la boîte de plantage de WFS-126) :
  titre « Nouvelle version disponible » ; texte « Construction N (commit abcdefg). Tu as la construction M. Ta sauvegarde
  est gardée. » ; boutons « Télécharger » (`Intent.ACTION_VIEW` sur l'adresse de l'APK : le navigateur télécharge, l'utilisateur
  installe par-dessus) et « Plus tard ». Toucher hors de la boîte ou Retour = « Plus tard ».
- RG-05 : « **Plus tard** » mémorise N (`wfs_maj.ignoree`) : la même construction n'est plus proposée ; une construction
  plus récente l'est de nouveau (au plus une fois toutes les 6 h, RG-01).
- RG-06 : **Jamais pendant une course** : la boîte n'apparaît que si l'écran natif est l'accueil ou le chargement ; si la
  réponse arrive plus tard, elle attend le prochain lancement. Si la boîte de plantage de WFS-126 est affichée à ce
  lancement, elle passe en premier et la mise à jour attend le lancement suivant. (Lire l'écran : `nativeEcran()` s'il
  existe déjà ; sinon, règle simple : la réponse n'est montrée que si elle arrive dans les **8 s** après `onCreate`, avant
  que l'utilisateur ait pu lancer une course — aucune modification de `src/**`.)
- RG-07 : **Boutons de volume** : `setVolumeControlStream(AudioManager.STREAM_MUSIC)` dans `onCreate` (ils règlent le son
  du jeu, plus la sonnerie, y compris dans les menus).
- RG-08 : **Preuves** : test JUnit `android/app/src/test/java/com/waforspeed/game/MiseAJourTest.java` (titre valide → N et
  commit ; N > M → proposer ; N ≤ M → rien ; N == ignorée → rien ; versionCode 1 → rien ; JSON cassé, sans pièce
  `WaForSpeed.apk`, titre sans numéro → rien) lancé par la CI (`gradle testReleaseUnitTest` dans le job `android`).
  Déclencheur de test pour l'APK (comme WFS-126 RG-05) : `adb shell am start -n com.waforspeed.game/.JeuActivity --ez
  wfs_maj_test true` affiche la boîte avec N = versionCode + 1 sans réseau.
- RG-09 : **Parcours complet (principe n°1 du PO)** prouvé au Journal avant fusion : (a) banc PC `WFS_BANC=parcours`
  (accueil → Course solo → Checkpoint → Continuer → garage → Choisir → terrain → Rouler → course → Retour = pause →
  Reprendre → fin → Menu → accueil) **0 écart** (aucun code natif changé) ; (b) job `android` vert avec les tests JUnit ;
  (c) dans `qa/Check.md`, la marche à suivre pour l'utilisateur : lancer l'APK de main, voir la boîte quand une
  construction plus récente existe, « Plus tard » → accueil → une course → retour à l'accueil sans boîte ; « Télécharger »
  → le navigateur télécharge `WaForSpeed.apk`.
