## Besoin
`tools/qa/tests_cpu.sh` lance seulement les fichiers `build/test_*` qu'il trouve (ligne 26 : `[ -f "$exe" ] && [ -x "$exe" ] || continue`).
Si un test est déclaré dans `CMakeLists.txt` mais n'a pas été construit (par exemple une erreur de liaison sur une construction partielle), il est sauté sans rien dire.
C'est arrivé : le script affichait « 116 réussis » alors que `test_langue` manquait.

## Règles de gestion
- RG-01 : le script lit la liste des tests déclarés dans `CMakeLists.txt` (`add_executable(test_…`, 117 aujourd'hui) et la compare aux exécutables présents dans le dossier de construction.
- RG-02 : chaque test déclaré sans exécutable donne une ligne `[ABSENT] test_xxx`. Le résumé final affiche le compteur « absents ». **Un seul absent fait sortir le script avec le code 1**, comme un échec.
- RG-03 : un test de la liste `IGNORES` (RG-05 du script) n'est pas compté absent.
- RG-04 : aucun autre changement de comportement : mêmes arguments, mêmes journaux, tous les tests lancés même après un échec (WFS-412). Aucun test désactivé, aucun seuil affaibli. `build.yml` et `matin.yml` ne changent pas (ils appellent déjà le script).
- RG-05 : vérification locale : (a) construction complète → 0 absent, code 0 ; (b) un exécutable `test_*` retiré du dossier → `[ABSENT]`, code 1. Ensuite, un run de `build.yml` sur la branche synchronisée avec `main` (US technique, numéro noté au journal).
