# WFS-236 — [TECHNIQUE] Robot des statuts : un run de main annulé seulement à la publication compte comme vert
Épic : E7 · Priorité : P1 Urgent · Dépend de : — · Origine : diagnostic de l'agent expert ci (journal 2026-11-07 13:03:39, commit 24ee9da), créée par le PO le 2026-11-07 13:05 UTC (règle « US techniques », 2026-11-06 23:18 UTC)

## Besoin (qui, quoi, pourquoi)
Depuis le run #817 (dernier vert), les runs de `main` #818, #820, #823, #825 finissent « cancelled » alors que **tous** leurs jobs de construction
et de test sont verts : seuls `publication-apk` et `publication-captures` sont annulés, parce que GitHub ne garde qu'un job en attente par groupe
de concurrence (`apercu-apk-refs/heads/main`, `apercu-captures-refs/heads/main`, `build.yml` l. 202 et 224). Le robot des statuts
(`tools/qa/statuts.py` l. 229-232) ignore les runs annulés : les tickets 🟣 (WFS-206, 210, 216, 217, 219, 220, 221, 223, 225…) ne passent jamais en ✅.

## Règles de gestion
- RG-01 : sur un run de `main` de conclusion `cancelled` (hors `schedule`), le robot relit la liste des jobs du run
  (`gh api repos/<dépôt>/actions/runs/<id>/jobs`, toutes les pages).
- RG-02 : si **tous** les jobs dont le nom ne commence pas par `publication-` ont la conclusion `success`, le run est traité **comme vert**
  (mêmes effets qu'un run `success` : tickets 🟣 du commit → ✅ avec le numéro du run, journal, `track-agent.md`) ; l'entrée du journal précise
  « annulé seulement à la publication ».
- RG-03 : sinon (un job de construction ou de test annulé, sauté, en échec ou absent) : **rien** (comportement actuel inchangé).
- RG-04 : **aucun** banc, seuil, test ni job de construction affaibli, retiré ou sauté ; aucun code fusionné retiré. Les jobs de publication restent tels quels
  (le changement de leur concurrence n'est pas dans ce ticket).
- RG-05 : tests ajoutés à `tools/qa/test_statuts.py` : (a) annulé avec seuls les `publication-*` annulés → vert ; (b) annulé avec un job de test annulé → rien ;
  (c) annulé avec un job en échec → rien ; (d) liste de jobs vide ou illisible → rien. Les tests existants restent verts.
- RG-06 (option) : rattraper les runs #818, #820, #823, #825 : relance à la main du robot (`workflow_dispatch` de `statuts.yml` s'il existe, ou exécution
  du script avec le numéro du run) ou, à défaut, passage manuel en ✅ avec le numéro du run, noté au journal.
- RG-07 : US technique : le développeur peut lancer la CI de sa branche (`workflow_dispatch` de `build.yml`, branche synchronisée avec `main`) autant de fois
  que nécessaire, **une à la fois**, chaque lancement noté au journal.
