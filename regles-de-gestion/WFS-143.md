## Besoin (qui, quoi, pourquoi)
L'utilisateur a modifié directement `configgame.json` sur `main` (commit e23fa51) : `poursuite.score_depart` 100 → 1000 ;
caméra poursuite `regard_devant` 14 → 10, `regard_hauteur` -6.3 → -4.5, zoom (fov poursuite) 66 → 64.
Depuis, la CI est rouge sur `main` et sur toutes les branches : job `texte` (`test_configgame` : « configgame.json du dépôt =
valeurs du code → ÉCHEC ») et job `vitrines` (« records (parcours) : records relus après redémarrage (ÉCHEC) »).
Ce sont des **choix de l'utilisateur** : on ne touche pas au JSON, on aligne le code dessus. Toutes les fusions en dépendent.

## Règles de gestion
- RG-01 : **`configgame.json` n'est pas modifié** (valeurs de l'utilisateur = référence). Le code s'aligne.
- RG-02 : valeurs par défaut dans `src/core/configgame.h` : `poursuite.scoreDepart = 1000` ; `camera.loin` = `{9.f, 6.3f, 10.f, -4.5f}`
  (recul, hauteur inchangés ; regard devant 10, regard en hauteur -4.5) ; `fov[0] = 64.f` (les 3 autres zooms inchangés).
- RG-03 : cause du job `vitrines` (trouvée par le PO) : `src/game/sauvegarde.cpp` l. 150 rejette à la relecture un record de
  poursuite dont le score dépasse 100 (`w[1] <= 100`). Remplacer la borne par la borne max de `poursuite.score_depart`
  dans `configgame.cpp` (1000), ou mieux par une borne qui ne dépend pas d'une constante en dur (≥ 1000 et ≥ score max atteignable).
  Accroche d'**une ligne** dans `sauvegarde.cpp` (zone de WFS-136, en cours) : à annoncer au Journal, conflit trivial attendu.
- RG-04 : vérifier qu'aucun autre code ne suppose un score de poursuite ≤ 100 (HUD `poursuite.cpp`, écran de fin, `records::poursuiteBat`,
  `tests/test_records.cpp`) ; les attentes chiffrées des tests qui reposent sur 100 sont mises à jour **vers les valeurs de l'utilisateur**,
  jamais l'inverse. Un affichage qui déborde avec 4 chiffres est corrigé par une accroche ≤ 10 lignes annoncée.
- RG-05 : `test_configgame` reste un garde-fou : il doit continuer d'échouer si le JSON et le code divergent (ne pas l'affaiblir).
- RG-06 : test de parcours complet (principe 000000) : le parcours des records du banc `vitrines` (accueil → Course solo → Checkpoint →

- RG-07 : fusion par confiance permise (> 50 %) une fois `test_configgame`, `test_records` et le banc `vitrines` verts en local ;
