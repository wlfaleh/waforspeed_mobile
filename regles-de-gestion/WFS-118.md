# WFS-118 — [URGENT] APK : même signature à chaque build (installer par-dessus, sans désinstaller)
Épic : E7 (`android/app/build.gradle`, `.github/workflows/build.yml`) · Priorité : P1 Urgent · Dépend de : — · Taille : 2 h · Retour de l'utilisateur (test réel, 2026-11-05) : « quand j'installe l'application Android je suis obligé de la supprimer avant, il me dit qu'il y a des conflits de package »

## Besoin
Chaque nouvelle version de l'APK doit s'installer **par-dessus la précédente**, sans désinstaller (et sans perdre la sauvegarde du joueur).

## Cause (lue dans le code par le PO)
`android/app/build.gradle` signe la version `release` avec `signingConfigs.debug`. Sur chaque machine de la CI, la clé de debug d'Android est **recréée à chaque build** : chaque APK a donc une **signature différente**, et Android refuse de remplacer l'application (« conflit de package »). Le `applicationId` (`com.waforspeed.game`) et le `versionCode` (numéro de build, qui augmente) sont corrects.

## Règles de gestion
- RG-01 : l'APK est signé avec **toujours la même clé**. Solution la plus simple, qui marche tout de suite : une **clé de test fixe** (`android/waforspeed-test.keystore`, mots de passe connus dans `android/keystore.properties` du dépôt) utilisée pour tous les APK d'aperçu et de `main` ; elle ne sert **jamais** pour le store.
- RG-02 : `signingConfigs` du `build.gradle` lit cette clé fixe (chemin, alias, mots de passe) ; plus de `signingConfigs.debug` pour la version `release` / APK d'aperçu.
- RG-03 : pour le store (plus tard), la clé de publication reste dans les **secrets** du dépôt (`WFS_CLE_ANDROID`, déjà prévue pour l'AAB) : ne rien changer à cette partie.
- RG-04 : `applicationId` inchangé ; `versionCode` continue d'augmenter avec le numéro de build ; la sauvegarde du joueur est conservée à l'installation par-dessus.
- RG-05 : preuve : deux APK de deux builds différents ont la **même empreinte de certificat** (`apksigner verify --print-certs` dans le journal de la CI) ; ligne ajoutée au journal de build.
- RG-06 : **une seule désinstallation sera nécessaire** une dernière fois (au passage de l'ancienne signature à la nouvelle) : le dire clairement dans les notes de la Release d'aperçu.
- RG-07 : **gel iOS** : ne toucher à aucun fichier iOS.

## Critères d'acceptation
- [ ] la CI affiche la même empreinte de certificat sur deux builds de suite
- [ ] l'utilisateur installe le build n°2 par-dessus le n°1 sans désinstaller
