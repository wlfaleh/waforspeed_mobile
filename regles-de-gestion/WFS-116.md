# WFS-116 — Bouton / geste « Retour » du téléphone : recule d'un écran au lieu de fermer le jeu
Épic : E7 · Priorité : P2 Haute · Dépend de : — · Taille : ½ à 1 jour · Créé par le PO le 2026-11-05 (sujet simple demandé par l'utilisateur)

## Besoin
Sur le téléphone, le **geste ou le bouton « Retour » d'Android** n'est pas géré : `onInput` (`src/platform/android_main.cpp`) ne traite que le tactile et les manettes (`manette_android.cpp` ne prend `AKEYCODE_BACK` que si la source est une manette) et renvoie `0` ; Android applique alors son traitement par défaut : `NativeActivity` se **ferme** (course perdue, rechargement complet au retour). Un joueur qui glisse depuis le bord de l'écran en pleine course quitte le jeu. Le « Retour » du téléphone doit faire exactement ce que fait le bouton « Retour » de l'écran affiché.

## Règles de gestion
- RG-01 : `AKEYCODE_BACK` venant de **n'importe quelle source** (clavier système, geste, bouton) est **consommé** par le jeu (`onInput` renvoie `1`), sauf au menu principal (RG-04). Action au **relâchement** (`AKEY_EVENT_ACTION_UP`), répétitions ignorées (`AKeyEvent_getRepeatCount > 0`), un seul cran par appui.
- RG-02 : action par écran — **Course** → Pause (comme `APP_CMD_LOST_FOCUS` et Start de la manette) ; **Pause** → reprise de la course ; **tout autre écran** (modes, garage, terrain, réglages, salon, fin de course) → même effet que son bouton « Retour » : **réutiliser** les zones déclarées par les écrans avec le drapeau `retour` (`manette::zonesPrecedentes()`, `src/platform/manette.h` l. 53) et le toucher simulé de `manette_jeu.cpp` (`toucher`, l. 26 ; logique de B l. 58-60). Ne rien recréer : aucune nouvelle table d'écrans.
- RG-03 : **Chargement** (et fondu du chargement) : appui consommé et ignoré.
- RG-04 : **menu principal** (aucune zone `retour`) : l'application passe en **arrière-plan sans être fermée** (`moveTaskToBack(true)` dans `JeuActivity.java`, en surchargeant `onBackPressed`, ou appel JNI) ; la sauvegarde est déjà écrite par `APP_CMD_PAUSE` (WFS-24). Au retour, le jeu reprend au menu, sans rechargement.
- RG-05 : le « Retour » du téléphone **ne bascule pas** en mode manette (pas de cadre de focus cyan) : ne pas passer par `manette::bouton(B)` ; une fonction séparée, par exemple `retourSysteme(Game&)` dans un nouveau `src/platform/retour_systeme.cpp/.h`.
- RG-06 (principe 000000) : **test CPU de parcours complet** (bureau, sans Android) appelant `retourSysteme` : accueil → Course solo → mode → Continuer → garage → Retour (téléphone) → mode → Retour → accueil ; puis accueil → … → course → Retour → Pause → Retour → Course → Retour → Pause → Menu ; puis accueil → Réglages → Retour → accueil. Chaque transition vérifiée (`Écran : a → b`), un seul cran par appui, aucun retour imprévu. Sortie recopiée au journal avant fusion.
- RG-07 : journal Android `WFS_LOG("retour (téléphone) : écran %s → %s")` à chaque appui, pour que l'utilisateur et le QA lisent la trace (`adb logcat`).
