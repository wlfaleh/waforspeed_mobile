## Règles de gestion
- RG-01 : **pendant l'écran de chargement existant** (WFS-35 / WFS-74), après les CGU (WFS-308), le jeu lit `cartes.json` (adresse
  `paquets.adresse_liste` de `configgame.json`, WFS-302 ; dernière copie gardée sur le téléphone), choisit le **format de texture** du téléphone
  (ASTC, sinon ETC2, sinon RGBA8, d'après ce que la carte graphique accepte), ignore la liste si `version_min_apk` est plus grand que l'APK, et
  appelle `verifier_carte` (WFS-301). Paquet de la Ville présent, juste et à jour → chargement léger, rien de plus (≤ 1 s de plus).
- RG-02 : sinon → proposition **« Mise à jour et installation des paquets »** dans l'écran de chargement : nom, **taille annoncée** avant tout
  téléchargement (« Ville, 210 Mo » ; > 200 Mo accepté par l'utilisateur), **« Wi-Fi conseillé »**, boutons « Installer » et « Plus tard ».
  **Règle Wi-Fi** : sur Wi-Fi, « Installer » est mis en avant ; sur données mobiles, la phrase « Vous êtes sur les données mobiles (210 Mo) »
  s'ajoute et rien ne part sans appui sur « Installer ».
- RG-03 : **téléchargement par un service Java** (`HttpURLConnection`, déjà utilisé dans `JeuActivity.java:223`), hors du fil de rendu : écriture
  dans `<fichier>.part`, **reprise par requête `Range`**, SHA-256 par `MessageDigest` comparé à `cartes.json`, puis renommage en fichier fini ;
  le C++ ne lit que des fichiers finis. Redirection de domaine suivie (GitHub Releases). Aucune bibliothèque ajoutée.
- RG-04 : affichage : **barre de la carte** (« Ville — 120 / 210 Mo ») et **barre totale**, temps restant (après 5 s), **messages / astuces sur le
  jeu** changés toutes les 6 à 8 s (≥ 15 textes courts en français, dans un fichier texte) ; ≥ 30 img/s.
- RG-05 : coupure, application fermée ou en arrière-plan → reprise là où il s'est arrêté (« Connexion perdue, reprise automatique ») ; SHA-256 faux
  → fichier effacé, retéléchargé une fois, puis « Réessayer ». L'ancien paquet est gardé jusqu'à ce que le nouveau soit vérifié.
- RG-06 : **secours hors ligne** (sans Internet, « Plus tard » ou échec) : le jeu démarre sur la **Ville construite par le code** (WFS-301 RG-06),
  sans message bloquant ; bandeau au menu « Paquet de la Ville disponible — Installer » ; dès que la connexion revient (vérifié au retour au menu,
  au plus une fois par minute), la proposition de RG-02 revient.
- RG-07 : place libre comparée à la taille + 10 % avant de commencer ; pas assez → « Place insuffisante : X Mo nécessaires, Y Mo libres » et secours.
- RG-08 : rien n'est envoyé hormis la demande des fichiers (l'hébergeur voit l'adresse IP : écrit dans la confidentialité, WFS-308) ;
  permission `INTERNET` déjà au manifeste, aucune autre.
- RG-09 : **essai sans WFS-302** avec un **faux paquet** (fichier servi par un petit serveur local du banc PC, ou Release de test du dépôt) :
  reprise, SHA-256 faux, coupure, place. **Essai réel** sur le téléphone de l'utilisateur dès que WFS-302 est fusionné (RG-06 de WFS-302) :
  durée sur Wi-Fi, place prise, durée du lancement avec paquet, poids de l'APK (journal).
- RG-10 : parcours complet : installation neuve → CGU → chargement → « Installer » → barres et astuces → menu → Ville → course → retour ;
  coupure du Wi-Fi au milieu puis reprise ; mode avion → Ville du code, bandeau, connexion revenue → proposition ; lancement suivant sans
  téléchargement. Captures au journal.

## Format de `cartes.json` (proposé par Claude, agent 3 (01UY1Vv3), 2026-11-08 ; à reprendre tel quel par WFS-302)
Fichier UTF-8 publié dans la Release `paquets` du dépôt, à l'adresse `paquets.adresse_liste` de `configgame.json`
(`https://github.com/wlfaleh/waforspeed_mobile/releases/download/paquets/cartes.json`). Lu par `ListePaquets.java` (règle pure, tests JUnit).
```json
{
  "version": 1,
  "paquets": [
    { "carte": "ville", "nom": "Ville", "format": "astc", "version_carte": 2,
      "empreinte": "c30f0f40c276b6c1", "version_min_apk": 950, "taille": 22771234,
      "sha256": "<64 chiffres hexadécimaux du fichier entier>",
      "adresse": "https://github.com/wlfaleh/waforspeed_mobile/releases/download/paquets/ville_astc.wfcarte" }
  ]
}
```
- `version` : version du format de la liste (1). Une liste plus récente que ce que le jeu sait lire est ignorée (secours).
- une entrée **par carte et par format de texture** (`astc`, `etc2`, `rgba8`), fichier `<carte>_<format>.wfcarte` produit par la cuisson de WFS-301 ;
- `empreinte` : empreinte du paquet en hexadécimal sur 16 chiffres (`carte::empreinte`, WFS-301 RG-02). Le jeu ne prend que le paquet dont
  l'empreinte est **celle qu'il attend** : un APK plus ancien ou plus récent ignore un paquet d'une autre génération (pas de paquet faux à l'écran) ;
- `version_min_apk` : versionCode minimal de l'APK (N de « 0.1.N ») ; `taille` en octets (annoncée avant tout téléchargement, place libre) ;
  `sha256` du fichier entier (vérifié par Java avant le renommage du `.part`) ; `adresse` en **https** seulement ;
- le jeu choisit, dans l'ordre ASTC, ETC2, RGBA8, le premier format que sa carte graphique lit et qui est dans la liste ;
- liste absente (404), coupée ou illisible = « pas de liste » : la carte du code est jouée, sans message bloquant (RG-06).
