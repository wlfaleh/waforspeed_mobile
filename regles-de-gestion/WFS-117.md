# WFS-117 — CI : lancer tous les tests CPU, y compris ceux oubliés (test_retour_systeme, test_commandes), sans liste à tenir à la main
Épic : E7 · Priorité : P2 Haute · Dépend de : WFS-116 ✅

## Besoin (qui, quoi, pourquoi)
Le développeur et l'utilisateur doivent pouvoir se fier à une CI verte. Aujourd'hui, la liste des tests CPU est écrite
à la main dans une seule ligne de `.github/workflows/build.yml` (étape « Test de la piste », groupe `texte`) :
- `test_retour_systeme` (WFS-116, touche Retour du téléphone, parcours menu → … → course → pause) est construit par
  CMake mais **jamais lancé** ;
- `test_commandes` (WFS-108, commandes tactiles, construit seul avec `TEST_COMMANDES_SEUL`) est construit mais **jamais lancé** ;
- chaque nouveau test (ex. celui de WFS-111, poursuite police, dont la zone interdit `.github/**`) sera oublié de la même façon.
Une régression sur ces sujets passerait donc la CI en vert et arriverait sur le téléphone de l'utilisateur.

## Règles de gestion
- RG-01 : nouveau script `tools/qa/tests_cpu.sh <dossier_build>` qui lance **tous** les exécutables `test_*` présents
  dans le dossier de construction (découverte automatique, triés par nom), un par un, et s'arrête en échec (code ≠ 0)
  dès qu'un test échoue, en nommant le test fautif.
- RG-02 : les arguments des tests qui en ont besoin sont dans une petite table du script, avec les valeurs actuelles de
  `build.yml` : `test_traffic tests/trafic_web_ref.txt`, `test_cartes tests/cartes_web_ref.txt`,
  `test_course tests/course_web_ref.txt`, `test_audio assets`, `test_roues assets`. Tout autre test est lancé sans argument.
- RG-03 : le script affiche, pour chaque test, une ligne `[OK] test_xxx (n s)` ou `[ÉCHEC] test_xxx`, puis un résumé
  `N tests lancés, N réussis`. Il échoue aussi si **aucun** test n'est trouvé (dossier faux).
- RG-04 : `build.yml`, étape « Test de la piste » : la longue ligne est remplacée par
  `bash tools/qa/tests_cpu.sh build && python3 tools/qa/verifier_licences.py` (la vérification des licences reste).
  Même condition `if: matrix.groupe == 'texte'` (pas de nouveau job, pas de minute de CI en plus).
- RG-05 : si `test_retour_systeme` ou `test_commandes` échoue une fois lancé, la correction est dans ce ticket
  **seulement** si elle tient dans le test lui-même (`tests/**`) ou en ≤ 10 lignes annoncées au Journal ; sinon, signaler
  au PO (ticket de correction) et désactiver ce seul test par une liste `IGNORES` du script, commentée avec l'ANO / le ticket.
- RG-06 : tous les tests passent en local avant la fusion (`cmake --build build && bash tools/qa/tests_cpu.sh build`),
  sortie collée au Journal (liste `[OK]` complète, dont `test_retour_systeme` et `test_commandes`).
- RG-07 : rien à changer pour les tickets suivants : un nouveau `add_executable(test_xxx …)` dans `CMakeLists.txt`
  est lancé tout seul par la CI (à écrire en 1 ligne dans le skill `waforspeed-natif`, partie tests, si le fichier le permet ;
  sinon au Journal).
