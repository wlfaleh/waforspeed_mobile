# WFS-515 — [TECHNIQUE] Essais réels des achats et de la pub (Play Console, comptes de test)
Épic : E21 / Publication app (aucun code du jeu ; `store/**` pour le compte rendu) · Priorité : P2 Haute · Dépend de : WFS-511 à 514 ; **compte marchand Google Play et compte AdMob ouverts par l'utilisateur** · Agent : agent expert ci cd (`@cicd`)
Règles communes : `regles-de-gestion/E21-market.md`. Après la fusion : **🟡 À valider (utilisateur)** (essai sur son téléphone).

## Besoin
Prouver sur un vrai téléphone, avec les outils de test de Google, que chaque achat et la pub marchent comme demandé, avant toute vente.

## Règles de gestion
- RG-01 **Guide pour l'utilisateur** (`store/market-essais.md`) : créer dans la Play Console les 6 produits avec les identifiants de WFS-510 RG-01 et les prix en euros de l'utilisateur
  (0,99 / 2,49 / 4,49 / 19,99 / 1,99 / 2,99 €, conversion automatique de Google) ; ajouter les **testeurs de licence** ; créer le compte AdMob, l'application et le bloc « récompensé » ;
  l'utilisateur met lui-même ses identifiants (jamais dans un message ni le journal, RC-E21-09). Aucune clé dans le dépôt.
- RG-02 **Piste de test interne** : AAB de `main` publié en test interne (même chaîne que WFS-319, sans sortie publique ; exception au « jour de publication » limitée au test interne, déjà permis par la décision du 2026-11-08 14:10 UTC).
- RG-03 **Scénarios** (cochés par l'utilisateur, captures du téléphone) : chaque pack acheté (carte de test « toujours approuvée ») et étoiles exactes ; « sans pub » ; désinstaller → réinstaller → « sans pub » revenu seul ;
  « Restaurer mes achats » ; achat interrompu (mode avion juste après le paiement, jeu tué) → étoiles créditées une seule fois au lancement suivant ; achat annulé ; carte « refusée » ; paiement en attente (« approuvé plus tard ») ;
  consentement refusé → le jeu marche ; vidéo de test vue en entier → ×2 ; fermée avant → rien ; 6e vidéo du jour → bouton caché ; mode avion en fin de course → bouton caché sans message.
- RG-04 **Compte rendu** dans `store/market-essais.md` : chaque scénario OK / KO ; un KO → anomalie au PO.
