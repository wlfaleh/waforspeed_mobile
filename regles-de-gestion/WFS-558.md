# WFS-558 — Interface R19 : scène 3D du duel en ligne (maquette 04)

## Besoin
L'écran du duel en ligne (`src/ui/ecrans/salon.*`) devient la scène de la maquette 04 : le parking souterrain, un **pilier** (bandes jaunes et noires en bas) qui porte la **plaque du pseudo** (« ALEX ») et un **digicode d'interphone** en métal brossé avec afficheur du code (« K 7 Q 2 »), la **voiture du joueur** garée entre deux lignes blanches, la **voiture de l'adversaire** à côté, panneau « Rejoins avec un code » en verre en haut à droite.

## Règles
- RG-01 Le **digicode est le clavier du code du salon** : appuyer sur ses touches tape le code (même format de code qu'aujourd'hui ; si le code a des lettres, le digicode a les touches nécessaires, modèle d'un vrai digicode alphanumérique) ; **une lettre par appui + 150 ms** (WFS-545) ; touche effacer et « OK » comme sur la maquette.
- RG-02 Digicode : dimensions d'un vrai digicode d'interphone mural (≈ 120 × 180 × 30 mm, touches ≈ 15 mm), métal brossé PBR, afficheur à cristaux liquides cyan ; pilier en béton aux arêtes chanfreinées.
- RG-03 2e voiture : la voiture de l'adversaire quand il est connu ; avant, une voiture garée du jeu (sans marque).
- RG-04 Toutes les étapes du salon (accueil, hôte, prêt, « Quitter le salon ») gardent leurs boutons ; les écrans sans place sur la maquette : demander au PO.

## Arbitrages du PO (2026-11-16 09:48 UTC, questions de Claude, agent dev3d (01Us6uCtQN))
- RG-05 **Taille du digicode : option A retenue.** Le digicode reste à **vraie taille** (RG-02, ≈ 120 × 180 × 30 mm) sur le pilier, dans le cadrage large de la maquette (voiture entière à l'écran) ; l'afficheur cyan est **allumé et visible** dans le cadrage large ; **le code tapé se lit en vue rapprochée** (à vraie taille, 82 × 18 mm, ses caractères font ≈ 3 px dans le cadrage large : illisibles, c'est normal). **Arbitrage du PO (2026-11-16 11:32 UTC, option A, demande du lead dev, PR #430 point 3)** : en cadrage large, s'il y a un code commencé, il est **aussi écrit dans le panneau de verre « Rejoins avec un code »**, sous l'aide (« Code : K7Q_ », 4 cases, même style que le code du salon) ; code vide → rien de plus dans le panneau. L'afficheur n'est **pas** agrandi (contraire à RG-02). **Un toucher sur le digicode** fait glisser la caméra (≈ 0,4 s, mouvement doux, sans saut) tout près du digicode, qui remplit la hauteur de l'écran (touches ≈ 90 px, pas ≈ 114 px ≈ 43 dp en 2400 × 1080) ; on tape le code ; « OK » rejoint le salon ; « Retour » (bouton 2D) ramène **d'abord** au cadrage large, puis un 2e « Retour » au menu principal. Le geste « retour » d'Android fait la même chose. L'option B (digicode agrandi ×4) est refusée : contraire à RG-02 et à `DA-realisme.md` (99 %). Écart avec la maquette accepté par le PO : la taille du digicode dans le cadrage large ; tout le reste de la maquette 04 reste à 100 %.
- RG-06 **Touches : pavé 6 × 6 retenu.** Touches de 15 mm au pas de 19 mm dans la face de 120 × 180 mm (sous l'afficheur) : les 31 caractères de `duel::CODE_CHARS` (2 à 9, puis A à Z sans I, L, O), puis sur la dernière ligne, après Z : **⌫** (2 touches de large) et **OK** (3 de large). Lettres gravées en majuscules sur les touches ; le code reste saisi et envoyé dans le format actuel (minuscules en interne si c'est le format). **Une lettre par appui + 150 ms** (WFS-545) ; pas de multi-appui façon téléphone. Pas de 0, 1, I, L, O (ils n'existent pas dans le code). Ce pavé remplace le pavé 1-9 de la maquette (écart accepté par le PO, imposé par RG-01).
- RG-07 **Écran d'accueil : recommandation retenue.** Pseudo **seulement sur la plaque 3D** (« ALEX » = le pseudo du joueur, sans marque). « Salons qui t'attendent » (Wi-Fi local) et « Derniers adversaires » (WFS-122), **seulement s'ils ne sont pas vides**, dans le panneau de verre « Rejoins avec un code » en haut à droite, sous l'aide, avec les mêmes tuiles qu'aujourd'hui (réutilisées, mêmes fonctions, FR / EN) ; le panneau grandit vers le bas sans recouvrir la voiture du joueur ni le bouton « CRÉER ».
