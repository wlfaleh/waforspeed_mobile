## Besoin
Le jeu parle français sur un téléphone en français, anglais sur tous les autres ; le joueur peut forcer la langue dans les Réglages.
Ce ticket pose **le système** (utilisé par WFS-505 à 508 et par tous les futurs écrans) et traduit **l'écran Réglages** pour le prouver.

## Règles de gestion
- RG-01 **Langue du téléphone** : au lancement, Android donne la langue du système (`Locale.getDefault().getLanguage()`, lue côté Java et passée
  au natif par JNI, comme `nativeMarges`). `fr` (fr-FR, fr-BE, fr-CA, fr-MA, fr-TN, fr-CH…, **quel que soit le pays**) → **français** ;
  **toute autre langue** → **anglais**. Langue illisible → anglais.
- RG-02 **Réglage « Langue »** (« Language » en anglais) : **Automatique** (par défaut) / **Français** / **English**. Les choix « Français » et
  « English » s'écrivent toujours dans leur propre langue. Automatique = RG-01. Une nouvelle ligne dans l'onglet **Affichage**
  (`reglages_onglets.h` : `L_LANGUE`, dernière ligne de l'onglet ; test `test_reglages_onglets.cpp` mis à jour). Aucun bouton ne change de taille.
- RG-03 **Changement à chaud** : le choix s'applique **tout de suite**, sans redémarrer : l'écran Réglages se redessine dans la nouvelle langue.
- RG-04 **Sauvegarde** : clé `langue=auto|fr|en` dans le fichier existant (`sauvegarde.cpp`) ; absente (ancienne sauvegarde) → `auto` ;
  aucune clé ancienne supprimée.
- RG-05 **Tables** : `assets/textes/fr.txt` et `assets/textes/en.txt`, format `cle=texte` (UTF-8, une ligne par clé, `\n` pour un retour à la
  ligne, `{1}`, `{2}` pour les valeurs : « {1} km/h », « Lap {1}/{2} »). Lues **au chargement** (`readAsset`, rien en course).
  `ui::tr("cle")` rend le texte de la langue active ; `ui::tr("cle", v1, v2)` remplit les valeurs. Clé absente : texte français + trace au journal
  (jamais de plantage, jamais de clé brute à l'écran).
- RG-06 **Test CPU** (`tests/test_langue.cpp`) : mêmes clés dans les deux tables ; aucun texte vide ; mêmes `{n}` des deux côtés ; RG-01 sur
  `fr`, `fr-CA`, `fr-MA`, `en`, `en-GB`, `ar`, `es`, `de`, `""` ; lecture d'une sauvegarde sans `langue` → `auto`.
- RG-07 **Garde-fou « phrase française »** : en mode banc (`WFS_LANGUE=en`), `ui::text` note chaque texte affiché ; le banc `WFS_BANC=textes`
  parcourt les écrans déjà traduits et échoue si un texte affiché en anglais contient une lettre accentuée française (é è ê à ç ù î ô û ë ï)
  ou un mot d'une petite liste de mots français courants (`le`, `la`, `les`, `des`, `du`, `une`, `et`, `pour`, `avec`, `vitesse`, `course`,
  `réglages`…), sauf liste blanche (noms propres inventés). Les tickets suivants y ajoutent leurs écrans.
- RG-08 **Garde-fou « texte qui dépasse »** : nouvelle fonction `ui::textBoite(r, x, y, largeur, hauteur, px, texte, …)` pour les textes posés
  dans un bouton ou une case : si le texte est trop large, la police est réduite **jusqu'à 20 %** ; au-delà, le banc `textes` le signale (échec)
  avec la clé, l'écran et la langue. Les boutons existants passent par elle au fil des tickets E20.
- RG-09 **Banc PC** : variable `WFS_LANGUE=fr|en` (sans elle : français, les captures existantes ne changent pas).
- RG-10 **Réglages traduits** : tous les textes de `reglages.cpp`, `reglages_onglets.h` (« Affichage », « Conduite », « Son ») et du panneau
  passent par `ui::tr` ; banc `textes` vert sur les 3 onglets en anglais.
- RG-11 **Android hors du jeu** : la boîte « Le jeu s'est fermé la dernière fois » (`strings.xml`) existe en anglais (`values/strings.xml`
  en anglais, `values-fr/strings.xml` en français) : elle suit la langue du téléphone.
