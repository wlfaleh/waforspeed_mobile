# WFS-112 — Duel entre amis par Internet : un vrai mode pour jouer avec ses amis, partout, mieux que la version web
Épic : E3 (+ accroches E7 `android/**`, E8 salon) · Priorité : P2 Haute · Dépend de : WFS-89 ✅, WFS-110 · Taille : 3 jours · Demande de l'utilisateur (`tache utilisateur.md`) : « revoir le duel en ligne, c'est pas normal le wifi, ce mode c'est pour jouer avec des amis ; trouve une solution pour faire même mieux que la version mobile (web) »

## Besoin
Aujourd'hui le duel marche surtout sur le même Wi-Fi (et WFS-92, le vrai pair PeerJS, bloque sur des bibliothèques tierces). Un joueur doit pouvoir inviter un ami **où qu'il soit** (4G, autre Wi-Fi) en deux gestes.

## Solution recommandée par le PO
**Serveur de relais WebSocket léger** (un petit programme à nous, hébergé gratuitement, p. ex. Cloudflare Workers) :
- fonctionne à travers toutes les box et la 4G (pas de blocage de pare-feu comme le pair-à-pair) ;
- côté jeu : connexion WebSocket sécurisée par l'API réseau d'Android (pas de bibliothèque tierce de 14 Mo, contrairement à WFS-92) ;
- côté jeu web : même protocole possible plus tard (compatibilité à étudier, pas obligatoire).
WFS-92 (libdatachannel) est **abandonné** au profit de ce ticket.

## Règles de gestion
- RG-01 : **Créer un duel** : choix de la voiture, du terrain et de la distance (2, 4, 6, 10 km) ; un **code à 4 caractères** et un **lien d'invitation** sont générés.
- RG-02 : **Inviter un ami en un geste** : bouton « Inviter » qui ouvre le **partage Android** (WhatsApp, SMS…) avec le lien ; **toucher le lien ouvre le jeu directement dans le salon** (lien profond) ; saisie manuelle du code possible aussi.
- RG-03 : le salon montre les joueurs (pseudo, voiture, prêt), la distance et le terrain ; départ quand tous sont prêts ; jusqu'à 4 joueurs ; **plus de mention du Wi-Fi** dans l'interface (le mode Wi-Fi local peut rester caché comme repli).
- RG-04 : course : **aucun trafic**, seulement les voitures des joueurs (WFS-110 RG-07) ; positions envoyées 10 fois par seconde, voitures adverses lissées (WFS-21 RG-04), nom au-dessus de la voiture.
- RG-05 : **mieux que le web** : reconnexion automatique après une coupure (30 s), affichage du ping, revanche en un bouton, mémorisation du pseudo, liste des derniers adversaires, classement et temps à la fin.
- RG-06 : sécurité : codes qui expirent (15 min), données reçues jamais crues (valeurs bornées), pas de données personnelles, pas de chat libre.
- RG-07 : le **serveur de relais** est écrit dans le dépôt (`serveur/`), testable en local, avec un test de bout en bout à 2 clients simulés ; **déploiement** : décision de l'utilisateur (voir plus bas).
- RG-08 : on veut que ça marche : une version à 2 joueurs par code et lien d'abord ; les 4 joueurs et les bonus ensuite.

## Décision prise par l'utilisateur (2026-11-04) : Cloudflare OK
Autoriser un petit serveur de relais **gratuit** (compte Cloudflare Workers à créer, ou autre hébergeur au choix). Recommandation du PO : Cloudflare Workers (gratuit, rapide, 5 min à mettre en place). Le relais est hébergé sur **Cloudflare Workers** (compte gratuit de l'utilisateur). Le développeur livre : le code du relais (`serveur/`), un script de déploiement (`wrangler`) et un **mode d'emploi en 5 lignes** pour que l'utilisateur crée le compte et déploie (ou lui donne un jeton d'API) ; l'adresse du relais est une constante du jeu. Tests de bout en bout en local d'abord.

## À réutiliser du jeu web
`js/net/duel.js` (salon, statuts, présence, `startDuelRace`, `finishDuel`, résultat) et `js/net/p2p.js` (interface salon) pour le protocole et les écrans ; natif : `src/game/duel*`, `reseau_*` (WFS-83, WFS-89).
