# WFS-185 — CI : plus de CI sur les branches ni les PR, CI de `main` seule après chaque fusion
Épic : E7 · Priorité : P1 Urgent · Dépend de : — · Origine : règle de l'utilisateur du 2026-11-06 (« les dev fusionnent puis valident sur la CI ; on évite les CI des PR qui bloquent les lanceurs »)

## Besoin
Chaque `git push` sur `feature/**` ou `claude/**` lance aujourd'hui toute la CI (`build.yml`) : les lanceurs sont occupés par les branches
et la CI de `main` attend. Le développeur fusionne puis valide sur la CI de `main` : la CI des branches n'est plus utile.

## Règles de gestion
- RG-01 : `build.yml` ne se lance plus sur un `push` de `feature/**` ni de `claude/**`, ni sur `pull_request`. Il reste : `push` sur `main`,
  `schedule` (endurance de nuit), `workflow_dispatch` (lancement à la main).
- RG-02 : `ios.yml` : retirer `feature/**` de son `push` (gel iOS : rien d'autre ne change dans ce fichier).
- RG-03 : sur `main`, deux fusions rapprochées : le run le plus ancien est annulé seulement s'il n'a pas commencé à publier (`concurrency`
  existante de WFS-106 gardée) ; chaque run écrit au résumé le commit et les tickets `WFS-XX` qu'il contient, pour que le développeur
  passe son ticket en ✅ avec le numéro du run.
- RG-04 : la Release `apercu` (captures de `main`) reste la référence de la QA ; les Releases `apercu-waforspeed-XX` ne sont plus créées
  que par un lancement à la main (RG-06) ; les anciennes ne sont pas supprimées.
- RG-06 : `workflow_dispatch` doit pouvoir viser une branche `feature/**` (seule CI de branche permise : fusion à confiance ≤ 50 %, lancée à la main, une fois) ; ses captures vont dans la Release `apercu-waforspeed-XX` de ce ticket-là.
- RG-05 : `paths-ignore` gardé (les commits de `TACHES.md`, journal, QA ne lancent rien).

## Zone de code
`.github/workflows/build.yml` (bloc `on:` et résumé), `.github/workflows/ios.yml` (bloc `on:` seulement). Rien d'autre.

## Critères d'acceptation
- [ ] un push sur une branche `feature/**` ne lance aucun run (vérifié sur la branche du ticket elle-même, après la fusion)
- [ ] la fusion sur `main` lance un run complet vert, résumé avec commit et tickets
- [ ] endurance de nuit et lancement à la main toujours possibles
- [ ] ligne `qa/Check.md` ; statut 🟣 puis ✅ avec le numéro du run
