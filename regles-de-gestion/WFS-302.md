# WFS-302 — [TECHNIQUE] Cartes cuites (2/4) : cuisson dans la CI, fichiers dans l'APK, poids contrôlé, mesure sur le téléphone
Épic : E7 · Priorité : P2 Haute · Dépend de : WFS-301 fusionné ; **fin du gel de la CI** (pas avant le 2026-11-09, comme WFS-294)

## Besoin (qui, quoi, pourquoi)
Que les cartes cuites de WFS-301 soient **dans l'APK** que l'utilisateur installe : la première partie se charge déjà sans construire la carte.

## Règles de gestion
- RG-01 : `build.yml` (et `matin.yml` s'il fabrique l'APK) lance `WFS_BANC=cuisson build/wfs_bench` **avant** l'empaquetage de l'APK et copie les
  `.wfcarte` dans les assets de l'APK (`assets/cartes/`). Pas de cuisson sur le téléphone.
- RG-02 : la CI cuit deux fois et compare les fichiers octet par octet (déterminisme, RG-05 de WFS-301) : différents → CI rouge.
- RG-03 : poids : la CI écrit dans le résumé du run le poids de chaque carte (brut, compressé) et le poids de l'APK avant / après ; au-delà du budget
  fixé (provisoire : 25 Mo compressés par carte) → CI rouge. Le budget est une constante du workflow, changée seulement sur décision de l'utilisateur.
- RG-04 : cuisson ratée → CI rouge (pas d'APK sans cartes cuites ; le repli de WFS-301 reste pour les cas imprévus sur le téléphone).
- RG-05 : **mesure sur le téléphone** (RG-06 de WFS-246) : temps de l'écran de chargement de la Ville et de la Corniche, APK avant / après, ligne
  « Rendu » / journal du jeu ; l'utilisateur valide (🟡 À valider après fusion).
- RG-06 : test de parcours complet sur l'APK : accueil → Ville → course → retour → Corniche → course → retour.

## À réutiliser
- `build.yml` existant (construction de `wfs_bench` pour le banc PC déjà présente), étape d'empaquetage Gradle actuelle ; ne pas changer le nom ni le
  chemin de sortie de l'APK, ni `versionCode` / `versionName`.

## Critères d'acceptation
- [ ] APK de `main` contenant `assets/cartes/ville.wfcarte` et `corniche.wfcarte` ; journal du jeu : « carte cuite chargée ».
- [ ] Double cuisson identique et poids dans le résumé du run ; contrôle du budget actif.
- [ ] Temps de chargement avant / après mesuré sur le téléphone de l'utilisateur.

## Hors périmètre
