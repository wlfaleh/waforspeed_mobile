## Règles de gestion
- RG-01 : la CI cuit la Ville actuelle dans les 3 formats de texture (WFS-301 RG-01), deux fois, et compare octet par octet : différentes ou
  cuisson ratée → CI rouge.
- RG-02 : publication sur une Release GitHub du dépôt, étiquette fixe `paquets` (même méthode que `tools/qa/publier_apercu.sh`), avec le
  `GITHUB_TOKEN` du workflow ; aucune autre clé. Un fichier par carte et par format.
- RG-03 : **`cartes.json`** publié avec les fichiers, spécifié ainsi : `version_liste` ; `version_min_apk` (`versionCode` minimal) ;
  `carte_par_defaut` = `"ville"` (décision de l'utilisateur) ; `cartes[]` : `nom`, `version`, `version_format`, `empreinte`, et pour chaque
  `format_texture` (`astc`, `etc2`, `rgba8`) : `taille`, `sha256`, `adresse`. Les adresses sont des **adresses directes de fichiers**
  (`browser_download_url`), **pas l'API GitHub** (limitée sans jeton).
- RG-04 : **adresse à un seul endroit** : `configgame.json` → `paquets.adresse_liste` (adresse directe de `cartes.json`) ; le jeu ne contient
  aucune autre adresse de paquet. Changer d'hébergement (Play Asset Delivery, Cloudflare R2) = changer cette valeur et la publication.
- RG-05 : résumé du run : taille de chaque fichier, poids de l'APK (inchangé : aucune carte dedans), lien de `cartes.json`.
- RG-06 : **sur le téléphone de l'utilisateur** : téléchargement réel par WFS-306 depuis cette Release (redirection de domaine de GitHub et reprise
  par `Range` vérifiées) ; l'utilisateur valide (🟡 À valider).
