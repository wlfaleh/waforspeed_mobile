# WFS-302 — [TECHNIQUE] Paquets de cartes (socle 2) : cuisson par la CI, publication sur GitHub Releases, liste `cartes.json`, adresse à un seul endroit
Épic : E7 (`build.yml`, `matin.yml`, `tools/qa/**`) + accroche ≤ 10 lignes `configgame.json` · Priorité : P2 Haute · Dépend de : WFS-301 fusionné ; fin du gel de la CI (pas avant le 2026-11-09)

> Décision finale de l'utilisateur (2026-11-08) : **GitHub Releases maintenant** (pour tester avec l'APK de la CI) ; l'adresse des paquets écrite
> **à un seul endroit** pour passer plus tard à Play Asset Delivery et / ou Cloudflare R2 sans refaire le jeu. Rien dans l'APK.

## Règles de gestion
- RG-01 : la CI cuit les cartes qui ont un paquet (`WFS_BANC=cuisson`), deux fois, et compare octet par octet : différentes ou cuisson ratée → CI rouge.
- RG-02 : publication sur une Release GitHub du dépôt, étiquette fixe `paquets` (à côté de `apercu`, même méthode que `tools/qa/publier_apercu.sh`),
  avec `GITHUB_TOKEN` du workflow ; aucune autre clé. Un fichier par carte (télécharger et supprimer chaque carte seule).
- RG-03 : liste `cartes.json` publiée avec les fichiers : pour chaque carte : nom, version de la carte, version du format, empreinte, taille,
  SHA-256, adresse du fichier ; `carte_par_defaut` = **`ville`** (décision de l'utilisateur, 2026-11-08) ; version minimale du jeu.
- RG-04 : **adresse à un seul endroit** : `configgame.json` → `paquets.adresse_liste` (adresse de `cartes.json`) ; le jeu ne contient aucune
  autre adresse de paquet. Changer d'hébergement (Play Asset Delivery, Cloudflare R2) = changer cette valeur et la publication, pas le jeu.
- RG-05 : résumé du run : taille de chaque paquet, poids de l'APK (inchangé : aucune carte dedans), lien de `cartes.json`.

## À réutiliser
- `build.yml` (construction de `wfs_bench`), `tools/qa/publier_apercu.sh` (publication d'une Release), lecture de `configgame.json` (WFS-128).
